# Security Policy

## Supported Versions

We actively maintain and provide security updates for the primary branch:

| Version | Status    |
| ------- | --------- |
| main    | Supported |
| < 1.0.0 | No        |

## Reporting a Vulnerability

The Haul core development team takes security and smart contract safety seriously. If you discover a security vulnerability or exploit risk—especially involving smart contract escrow, custody of funds, relayers, or authentication—please **do not report it through public GitHub issues**.

Instead, please report vulnerabilities privately:

1. **Email:** Contact the maintainer at `opeyemimoses@users.noreply.github.com` with the subject line `[SECURITY] Haul Vulnerability Report`.
2. **Details to Include:**
   - Detailed description of the vulnerability.
   - Proof of Concept (PoC) or step-by-step reproduction guide.
   - Affected smart contracts, functions, or frontend modules.
   - Assessment of potential impact (e.g., loss of funds, unauthorized state transition, denial of service).
   - Any suggested mitigations or patches.

## Security Response Process

- **Acknowledgment:** We will acknowledge receipt of your report within 48 hours.
- **Investigation:** We will evaluate the impact and verify the PoC.
- **Remediation:** If verified, a patch will be prepared and tested privately before public deployment.
- **Disclosure:** We will coordinate responsible public disclosure once the fix has been applied.

Thank you for helping keep the Haul protocol and its users safe.
